## 三、速度

| 变体 | 请求数 | 决策数 | 决策/请求 | ms/请求 | 总耗时 |
|---|---|---|---|---|---|
| Laya | 25,673 | 25,673 | 1.00 | **23.5** | 10.1 min |
| Qwen 零样本 | 6,065 | 24,473 | **4.04** | 140.9 | 14.2 min |
| Qwen 训练后 | 7,265 | 25,673 | 3.53 | 140.3 | 17.0 min |

Laya 单次快 6 倍，但一次只答一个问题；我们的引擎一次前向答 3.5–4 个（多问题任务最多 28 个），
所以全量 2.5 万个决策的总耗时只差 1.4 倍。这次为了跑完全量，我给引擎加了**多 state 批量推理**
（一次前向算 16 条 item），实测同一任务 16.3s → 2.9s，**快 5.6 倍且准确率完全一致**。

## 四、坏消息：你训练的这个头比零样本差（已定位原因）

| | bool | choice | score |
|---|---|---|---|
| 零样本 | **0.702** | **0.663** | 0.661 |
| 训练后 | 0.341 | 0.481 | **0.686** |

训练后的头在两个题型的**校准也崩了**（ECE 0.6–0.9），个别任务甚至掉到随机以下（goemotions 0.249）。

**原因不是训练不收敛，而是类别平衡采样把先验拉歪了。** 直接证据：

```
goemotions 测试集（60 条 × 28 问）：真实正例率 4.3%
  零样本读出   平均预测 P(yes) = 0.407   ← 已偏高，但排序仍然有用（准确率 0.722）
  训练后的头   平均预测 P(yes) = 0.760   ← 严重高估（准确率 0.249）
```

两边都偏向"是"，但训练后那个几乎把正例率当成 76% 在用。

`train.py` 默认开启了类别平衡（按 [选项集合, 标签] 分组，把少数类过采样到与多数类等量），
本意是修上一版"一律答否"的坍缩；但这次**矫枉过正**：头学到的先验≈50%，
遇到真实正例率 4% 的 goemotions/jigsaw 时就会大面积误报"是"，
准确率自然从 0.72 掉到 0.25（多数类基线 0.958）。

### 建议的修法（任选，或组合）

```bash
# A. 不做平衡，用自然先验训练（推荐先试这个，~6 分钟）
python train.py --no-balance --max-samples 6000 --epochs 1

# B. 温和平衡 + 多跑一轮
python train.py --max-samples 12000 --epochs 2

# C. 训练后做温度校准（把 ECE 拉回 0.05 量级），再评测
python -m qwenjev.cli train --dataset synthetic ...   # 或直接用 API 里的 /v1/decide + 校准脚本
```

然后用 `python test.py` 重跑对比即可（脚本会自动读 `models/qwenjev-multitask-v2/readout.pt`）。
