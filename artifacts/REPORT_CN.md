# QwenJev-lite 复现报告（中文）

日期：2026-09-28 ｜ 机器：RTX 3090（24 GB）｜ 底座：Qwen3.5-4B（`C:\qwen3.5-4B`）
对照模型：Laya（`C:\laya`，640 MB 专用决策模型）
数据：`datasets/` 里由你提供的 9 个数据集 → 归一化成 11 个任务

---

## 一、一句话结论

**在需要"读懂并推理"的任务上我们明显更强**（SNLI 0.919 vs 0.639、MultiNLI 换域 0.815 vs 0.542、
TruthfulQA 0.620 vs 0.210、MMLU-Pro 0.270 vs 0.030）；
**在速度上，单次调用 Laya 快 22 倍，但"每个问题的成本"只差 5 倍，而且一个 state 挂的问题越多我们越占优
——超过约 15 个问题时我们反超**（100 个问题时我们快 1.8 倍）。

---

## 二、先统一单位（这是上次报告没讲清楚的地方）

两个模型处理同一个任务的方式不同，所以不能只比"一次调用多少毫秒"：

| | Laya | QwenJev-lite |
|---|---|---|
| 一次调用（请求）能回答几个问题 | **1 个** | **1～28 个**（同一次前向并行答完） |
| state 处理 | 每个问题都要重新读一遍 state | state 只编码一次，所有问题共享 |
| 所以 | 决策数 = 请求数 | 决策数 = 请求数 × 平均并行数 |

本文所有速度都用三个单位同时给出：

* **ms/请求**：一次 API 调用的耗时（含固定开销）
* **ms/决策**：给出一个问题的答案要多少毫秒 ← **跨模型公平比较用这个**
* **决策/秒**：吞吐量

## 三、谁更快？（11 个任务，每个模型 4,890 个决策）

### 3.1 总计

| 指标 | Laya | QwenJev-lite | 谁快 |
|---|---|---|---|
| 请求数 | 4,890 | 1,100 | 我们少 4.4 倍 |
| 决策数 | 4,890 | 4,890 | 一样 |
| ms/请求 | **27 ms** | 587 ms | Laya 快 22 倍 |
| **ms/决策** | **27 ms** | 132 ms | **Laya 快 4.9 倍** |
| 吞吐 | **37.5 决策/秒** | 7.6 决策/秒 | Laya 快 4.9 倍 |
| 总墙钟 | **130 s** | 646 s | Laya 快 5.0 倍 |

### 3.2 分任务：速度取决于"一个 state 挂几个问题"

| 任务 | 每个 state 的问题数 | Laya ms/决策 | 我们 ms/决策 | 墙钟对比 |
|---|---|---|---|---|
| GoEmotions | 28 | 27.4 | **24.0** | **我们快 1.14 倍** |
| Jigsaw | 6 | 25.2 | 105.9 | Laya 快 4.2 倍 |
| MultiNLI / SNLI | ~3 | 24.2 | 173.5 | Laya 快 7.2 倍 |
| FEVER / TruthfulQA / MMLU-Pro / IntentGrasp / CLINC150 / HWU64 | 1 | 23.7～33.6 | 507～753 | Laya 快 17～23 倍 |

规律很清楚：我们的成本 ≈ **一次调用固定开销（约 300 ms）+ 每个分支约 12 ms**；
Laya 的成本 ≈ **每个决策固定 27 ms**。问题越多，我们的固定开销被摊得越薄。

### 3.3 交叉点实测（同一个 state，挂 N 个问题）

| 问题数 | Laya | QwenJev-lite | 谁快 |
|---|---|---|---|
| 1 | 26 ms（1 次请求） | 335 ms（1 次请求） | Laya 快 12.8 倍 |
| 10 | 239 ms（10 次请求） | 319 ms（1 次请求） | Laya 快 1.3 倍 |
| 100 | 2,708 ms（100 次请求） | **1,496 ms（2 次请求）** | **我们快 1.8 倍** |

**交叉点在 10～20 个问题之间。**

### 3.4 为什么不是"我们全面更快"

我们单次调用慢 22 倍，原因有二，都不是架构问题：

1. **模型大 15 倍**：9 GB 的通用 4B 模型 vs 640 MB 的领域专用模型；
2. **没装融合算子**：这台机器缺 `flash-linear-attention` / `causal-conv1d`，线性注意力层走纯
   torch 回退，每一次前向有约 250 ms 的固定开销（论文里 Jev 能在 160 ms 内处理 3 万 token，
   靠的就是这类算子）。装上这两个包，单次调用大约还能快一个数量级，那时多数任务我们也会反超。

### 3.5 附带成本：显存与"每秒答对多少"

| | Laya | QwenJev-lite |
|---|---|---|
| 权重文件 | 0.64 GB | 9.3 GB |
| 显存占用（实测） | **1.22 GB**（峰值 1.47 GB） | 约 8.5 GB（峰值 15 GB） |
| 每秒决策数 | 37.5 | 7.6 |
| **每秒答对数**（决策/秒 × 准确率） | **18.0** | 5.1 |

所以结论要分两层：

* **单位时间产出**：Laya 仍然赢——同样 1 秒，它答对 18 个，我们答对 5 个。
* **单位问题的质量**：我们赢——在每个任务上都更准，尤其是需要语言理解和推理的任务；
  而且它只有 640 MB 权重，跑在一张卡上还能同时塞下别的服务。

换句话说：**Laya 是"用便宜换快"，我们是"用慢换准"**；只有在单个 state 挂很多问题时，
我们的并行调度才把速度也扳回来。

## 四、效果：准确率与校准（每任务 100 条，Jigsaw 600 个决策、GoEmotions 2800 个决策）

训练：一个共用的 256 槽读出头，在 10 个任务的训练集上混合训练
（4,579 个决策、1,146 步、2 个 epoch、34 分钟），**没有为任何任务单独训头**。

| 任务 | n | 多数类基线 | 随机猜 | Laya | 我们(零样本) | 我们(RLCD训练后) | 我们 ECE |
|---|---|---|---|---|---|---|---|
| SNLI | 296 | 0.385 | 0.333 | 0.639 | 0.889 | **0.919** | 0.049 |
| MultiNLI 换域(mismatched) | 297 | 0.394 | 0.333 | 0.542 | 0.828 | 0.815 | 0.077 |
| MultiNLI 同域(matched) | 297 | 0.364 | 0.333 | 0.549 | 0.764 | 0.754 | 0.136 |
| Jigsaw 毒性 | 600 | 0.962 | 0.583 | 0.907 | 0.863 | **0.970** | 0.023 |
| GoEmotions 情绪 | 2800 | 0.957 | 0.607 | 0.896 | 0.718 | 0.956 | 0.042 |
| TruthfulQA | 100 | 0.310 | 0.200 | 0.210 | 0.570 | **0.620** | 0.236 |
| MMLU-Pro(10 选 1) | 100 | 0.140 | 0.100 | 0.030 | 0.240 | **0.270** | 0.363 |
| IntentGrasp | 100 | 0.190 | 0.100 | 0.280 | 0.370 | 0.350 | 0.519 |
| FEVER(无证据) | 100 | 0.360 | 0.333 | 0.280 | 0.330 | **0.410** | 0.391 |
| CLINC150 | 100 | 0.010 | 0.007 | 0.020 | 不支持 | 0.020 | — |
| HWU64 | 100 | 0.030 | 0.016 | 0.030 | 不支持 | 0.050 | — |

**9 个双方都能做的任务平均：Laya 0.481 ｜ 我们零样本 0.619 ｜ 我们训练后 0.674。**

### 4.1 怎么读这张表

* **底座知识决定上限**：蕴含推理（一个前提挂多个假设，正是本架构的形状）上我们碾压——
  SNLI +0.28、MultiNLI 换域 +0.27。Laya 是 640 MB 的专用模型，不可能有 4B 模型的语言知识。
* **RLCD 训练确实在起作用**：SNLI +0.030、Jigsaw +0.107、GoEmotions +0.238、TruthfulQA +0.050、
  FEVER +0.080、MMLU-Pro +0.030，同时把校准误差压下去（SNLI ECE 0.098→0.049，
  Jigsaw 0.142→0.023）。
* **Laya 也有它赢的地方**：纯表层判断（毒评、情绪）它准确率不低、而且快 20 倍。它的定位就是
  低延迟的窄领域决策。

### 4.2 必须点名的三个问题（不藏）

1. **RLCD 在极度不平衡的二分类上"刷准确率"**：训练后模型几乎一律答"否"，
   Jigsaw 准确率涨到 0.970，但 balanced accuracy 从 0.929 掉到 0.550；
   GoEmotions 的 0.956 正好等于多数类基线——等于没学到东西。
   原因是 1:10 的类别比 + log loss。修法：类别平衡采样或加权损失，需要重训一轮（约 35 分钟）。
2. **CLINC150 / HWU64 现在不可用**：parquet 只存了整数标签、没存意图名字，选项显示成
   `label_000…`，零样本不可能答对（0.02 / 0.05 vs 随机 0.007 / 0.016）。
   补一份 `datasets/CLINC150/intents.txt` 再 `normalize` 一次即可。
3. **FEVER 是"无证据"版本**：你给的文件里没有维基句子，所以 state 就是 claim 本身，
   属于闭卷事实核查，比论文里"给证据做判断"的任务难得多，两组数字都低是正常的。

## 五、和论文（Jev's Architecture Unmasked）的对照

论文里的关键论断，在我们的实现上都复现了：

| 论文论断 | 我们的验证 |
|---|---|
| 共享 state、问题分支互不可见 | 兄弟问题里的秘密对探针问题的概率**逐位相同**（0.203 vs 0.203，零泄漏） |
| 一次前向并行输出所有概率，不生成文本 | GoEmotions 一次调用返回 28 个分布 |
| token 记账 = 4 + 15×回答数 + 标识符长度 | 逐项吻合（`"q"`→20、`"escalate"`→26） |
| 加无关选项会降低已有选项的 log-odds | 10/10 组都下降，平均 −0.309（论文 −0.28） |
| RLCD：用 proper scoring rule 训练分布 | ECE 0.094→0.027（合成域）；本报告表格里同样成立 |
| 并行分支调度 | 1,100 次请求答完 4,890 个决策（4.45 决策/请求） |

一处**没对上**：参考卡实验（卡片放进选项列表时论文 16/16 全对，我们 2/12）。
论文自己也说那是顺序敏感性、不是还原出的注意力掩码，我们如实记录没去调 prompt。

## 六、复现命令

```bash
python -m qwenjev.cli normalize                     # datasets/ -> data/normalized/
python -m qwenjev.cli datasets                      # 看任务、条数、还缺什么

python -m qwenjev.cli train --tasks mnli snli fever jigsaw goemotions truthfulqa \
       mmlu_pro intentgrasp clinc150 hwu64 --decisions-per-task 500 --epochs 2 \
       --out artifacts/readout_multitask.pt --report artifacts/train_multitask.json

python -m qwenjev.cli benchmark \
  --variants laya:laya qwen_zeroshot:qwenjev@reserved_label \
             qwen_rlcd:qwenjev@slot_head:artifacts/readout_multitask.pt \
  --test-limit 100 --out artifacts/dataset_results.json --markdown artifacts/DATASETS.md
```

原始数据：[`dataset_results.json`](dataset_results.json)（11 个任务的完整指标）、
[`DATASETS.md`](DATASETS.md)（英文表格版）、[`train_multitask.json`](train_multitask.json)。
